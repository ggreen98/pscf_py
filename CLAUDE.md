## Domain context
- **PSCF** (Potential Source Contribution Function): a receptor modeling technique that identifies likely source regions for air pollutants. It works by binning back-trajectory endpoints onto a grid and computing the fraction of trajectories arriving during high-pollution episodes.
- **traPSA**: the reference implementation (Clarkson University / CARES). Windows-only MATLAB app. User guide is at `TraPSA Software User's Guide.pdf` in this directory.
- **Back trajectories**: generated by HYSPLIT. Each trajectory is a time series of lat/lon endpoints tracing where an air parcel came from. TraPSA generates one trajectory per concentration measurement timestamp.
- **Key variables**: `n_ij` = total trajectory endpoints in grid cell (i,j); `m_ij` = endpoints where the paired concentration exceeded the threshold. `PSCF_ij = m_ij / n_ij`.

## traPSA conventions (confirmed from user guide)

### Time pairing
- TraPSA generates trajectories "based on pollutant measurement date" — one trajectory per measurement hour.
- Trajectory files "must have identical date information corresponding to the concentration data."
- **Convention: same-label, no offset.** Trajectory initialized at hour H is paired with the measurement whose timestamp is H. No +1 or -1 hour adjustment.
- **All data must be in the same time base before pairing.** Boulder Air data is in UTC. EPA AQS data should be converted to UTC. The few years of BRZ Boulder Air data recorded in MST must be converted to UTC.
- AQS labels the *start* of the averaging period (e.g., label 12:00 UTC = average over 12:00–13:00 UTC). Boulder Air minute data should be resampled to hourly using the same convention (left-label / closed-left).

#### Why trajectory H pairs with label H (not H-1)
A back trajectory initialized at H represents an air parcel that arrived at the receptor at time H. That air then sat at the receptor during H to H+1, contributing to the concentration measured during that period. AQS label H = average over H to H+1, so it captures the same air the trajectory describes. Pairing with label H-1 (the hour *ending* at H) would describe air that had already passed through before the trajectory-initialized parcel arrived.

The trajectory is instantaneous while the concentration is a 1-hour average, so there is inherent ±30 min ambiguity — label H and label H-1 are equally imprecise relative to the instantaneous trajectory time. Pairing H=H is chosen for physical consistency and to match traPSA convention. HYSPLIT trajectory positional uncertainty (typically 15–20% of travel distance per day) far exceeds this pairing ambiguity anyway.

#### Per-species hourly resampling convention
Different species use different resampling methods, chosen for consistency across data sources:

- **O3 and NOx** (BA + CDPHE): floor to hour (left-label, closed-left). BA minute data is resampled as `resample('1h', closed='left', label='left').mean()`. This matches AQS left-label convention exactly, so BA and CDPHE sites are directly comparable.
- **VOCs** (BA only, no CDPHE equivalent): round to nearest hour. BA VOC data is a ~10-minute grab sample taken near the top of the hour. Since there is no CDPHE VOC data to be consistent with, rounding is more accurate than flooring — a sample at 12:05 correctly lands on 12:00. Early years of data had less strict sampling times (samples occasionally later in the hour), but since O3/NOx consistency is not a constraint for VOCs, rounding remains the best choice.

### Threshold (criterion value)
- **Per-site criterion, not network-wide.** In multi-site mode, each site s gets its own threshold C_s.
- traPSA default: **0.8**, meaning the 80th percentile of that site's own concentration distribution.
- The range cited in the guide is 50%–90% of the highest concentration.
- `p_s,l = 1` if `c_s,l >= C_s`, else 0.

#### Decision: compute C_s post-merge (on trajectory-paired data), not pre-merge
`C_s` is computed on the concentration data *after* it's inner-joined with the trajectory endpoints (i.e., on `BRZ`, not `BRZ_data`) — meaning only hours that have a matching trajectory file contribute to the threshold. This was a deliberate choice, not an oversight:

- **traPSA itself doesn't have this ambiguity.** TraPSA generates one trajectory per measurement by construction, so in the reference tool "paired" and "full record" are the same set. The pre/post-merge distinction only exists in this Python reimplementation because the HYSPLIT trajectory archive has gaps (missing files, failed runs) that traPSA's own workflow wouldn't have. So matching traPSA doesn't decide this either way.
- **Large-N robustness.** With many thousands of hours per site, dropping the unpaired subset before computing an 80th-percentile quantile barely shifts the estimate, *as long as* trajectory-file gaps aren't systematically correlated with concentration level (e.g., HYSPLIT failures clustering on specific synoptic patterns). No evidence of that kind of systematic gap was identified.
- **Matches convention used by other common PSCF tooling** (e.g., openair in R), which computes descriptive statistics on the already-paired dataset rather than the full raw concentration record.
- **Analysis is intentionally scoped to summer daytime ozone** — this is a deliberate subsetting choice (not incidental missingness), so the threshold is meant to characterize "high ozone" specifically within that scope, not the full year-round/24-hour record. This scoping should happen *before* the merge, upstream of both the threshold computation and the trajectory join.

Pipeline order: filter to summer + daytime hours → inner-join with trajectories → compute `C_s` (80th percentile) and flag `p_s,l` on the merged, filtered frame.

If a future validation run against traPSA shows a mismatch traceable to the threshold, this is the first assumption to revisit — recomputing `C_s` pre-merge (on the full filtered record before joining) is the fallback if trajectory-archive gaps turn out not to be random with respect to concentration.

### Multi-site PSCF formula
```
PSCF_ij = sum_s( sum_l( p_s,l * tau_ij_s_l ) )
           / sum_s( sum_l( tau_ij_s_l ) )
```
Where s = site, l = trajectory, tau = endpoint count in cell (i,j). Sites contribute to the same shared grid; n_ij and m_ij accumulate across all sites.

### Weighting function (trailing effect correction)
Cells with low endpoint counts get a penalty weight to suppress false source regions ("trailing effect"). The weight is a step function of `n_ij` relative to `avg` (average endpoints per cell across the whole grid):
- `avg = total_endpoints / num_cells`
- Weight levels are user-defined (no traPSA defaults supplied for the levels themselves).
- Applied as: `W_ij = PSCF_ij * weight(n_ij)`
- **Literature-standard scheme (Polissar et al.), as implemented in openair's `trajLevel.R`** — verified directly against openair source ([github.com/davidcarslaw/openair/blob/master/R/trajLevel.R](https://github.com/davidcarslaw/openair/blob/master/R/trajLevel.R)):
  - `n_ij > 2*avg` → weight = 1 (no reduction)
  - `avg < n_ij <= 2*avg` → weight = 0.75
  - `avg/2 < n_ij <= avg` → weight = 0.5
  - `n_ij <= avg/2` → weight = 0.15
  - Note: bottom tier is **0.15**, not 0.25 — this was corrected after checking openair's actual source (2026-07-24).

### Other traPSA parameters (defaults)
- CPF minimum wind speed: 5 km/h (low-speed observations discarded from CPF)
- CPF criterion: 0.8 (80th percentile)
- PSCF criterion: **0.8** (80th percentile, per site)
- Grid smoothing: 3×3 neighborhood mean (`G_ij = mean of all non-missing neighbors`)
- Peak identification: top 10 grid cells by default
